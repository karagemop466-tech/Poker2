Repo review

The brief asked for the repository to be reviewed line by line, with official links, flagging irregularities. This page is that review, applied to the repository itself rather than to the casinos: what was duplicated, what was asserted without a source, what has been corrected, and what is still standing.

The one that mattered

Earlier revisions of this repository described the MGM Grand $120 daily as the best confirmed single-entry candidate, on the grounds that its structure sheet never mentions re-entry. That is an inference from silence, and it is the exact failure mode the brief forbids. A sheet that does not mention re-entry is silent; a sheet that says "re-entry is not allowed" is evidence. Only the second one confirms anything.

The dataset now encodes that distinction as a field value rather than a footnote: entry_rule = "not_stated" is separate from any confirmed rule, the single-entry filter returns zero rows, and the ranking page explains the zero instead of hiding it.

What is still wrong, and is not fixed here

  • Four trees still exist. The old dashboards are archived, not deleted. Deleting them is a repository-history decision, not a research decision, and it belongs to whoever owns the repo.
  • Two JSON datasets still overlap. data/tournaments.json and data/verified/*.json are still on disk. They are no longer linked from the live site, but they are still there and still hold older values.
  • The generator is not scheduled. Nothing re-checks a source automatically. Every "last checked" date on this site is the date of a human-driven read, and it ages from the moment of the build.
  • Two venue pages have almost nothing on them. Bellagio has two events and Horseshoe has six rows with no buy-in at all. That is the true state of the research, not a rendering bug.

How to re-run everything

python3 scripts/poker_data.py        # data/poker/dataset.json  (the numbers)
python3 scripts/build_dashboard.py   # index.html, events.html, … (the pages)
python3 scripts/check_links.py       # optional: resolve every outbound link

The generator is deterministic. Rebuilding without changing the data produces byte-identical HTML, which is what makes a diff in a pull request meaningful.

Verification rule for this site. Every table row links to the official page, PDF or structure sheet the value came from, and shows the date that source was last read (2026-11-16). A cell showing — means no official source stated the value. Nothing is inferred or filled in. Guarantee ÷ entry fee is a descriptive ratio, not a forecast of winnings.
