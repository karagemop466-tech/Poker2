A GitHub Actions workflow runs scripts/recheck_sources.py on a schedule, fetches every official URL above, hashes the normalised text of each page, and appends any change to data/site/checks.json. The workflow fails nothing on a content change: a change is recorded, not guessed at.

What is monitoredHow a change is surfaced
Every URL in the register aboveText hash comparison per run; changed rows are listed in data/site/checks.json with the old and new hash and a timestamp.
HTTP failures (404 / 500 / timeouts)Recorded as a fetch error, which is itself a flag: a moved page can invalidate a cited value.
Schedule cadenceDaily at 06:00 UTC, plus manual dispatch from the Actions tab.

Why monitoring rather than a scraper per room: the Venetian, Wynn and Caesars PDFs are directly fetchable and are what this dataset is built on; Horseshoe publishes no retrievable tournament document at all, so no scraper can invent one.
