# Vegas poker trip planner

A static, source-audited planner for a Las Vegas Strip poker trip: which one-day tournaments are
actually open to a single-entry plan, and what the same stay costs at the hotels that can reach that
poker room on foot. Every number on the site is either quoted from an official page with its
retrieval date, or left blank and listed as a flag. Nothing is inferred.

Published by GitHub Pages from the repository root: <code>index.html</code>.

## Data flow (all three steps are deterministic and checked in CI)

```
official pages (read by hand)            transcribed + cross-checked                generated HTML
scripts/build-events.py  ->  site-data/*.json  ->  scripts/build-site.py  ->  *.html, assets/
                                 ^
        scripts/check_sources.mjs + scripts/scrape-schedule.mjs (daily in Actions)
```

| File | What it is |
| --- | --- |
| `site-data/events.json` | 94 published rows of the Venetian DeepStack Extravaganza IV schedule; per-rule `{value, status, excerpt, source_url, retrieved}` objects. Generated by `scripts/build-events.py`, which aborts if a guarantee in an event name disagrees with its structure sheet, or if an event is tagged to a sheet that does not list it. |
| `site-data/schedule.json` | one primary event plus a conditional evening fallback for each day, four-day windows, overlap flags, and the days that have no plan. Generated by `scripts/build-schedule.py`. |
| `site-data/hotels.json` | resort fee, parking, incidentals, occupancy surcharge, cancellation window and address per property, each with its verbatim excerpt and source URL. |
| `site-data/rates.json` | dated rate log: what was published, when, for which dates, under what conditions. Entries append; nothing overwrites a previous capture. |
| `site-data/walk.json` | hotel &rarr; poker-room pairs. Route statements are quoted where official; minute durations are blank because none are published. |
| `site-data/venues.json`, `other-venues.json` | per-room facts and coverage state; other Strip rooms' rows are labelled "cited, not re-read" and excluded from ranking. |
| `site-data/sources.json` | every monitored official URL with the values extracted from it, plus third-party leads marked `used_as_value_source: false`. |
| `site-data/flags.json`, `questions.json`, `suggestions.json`, `summary.json` | the unverified list, the decision questions with their state, implemented vs awaiting-your-choice improvements, and the executive summary. |
| `site-data/change-report.json`, `schedule-diff.json`, `snapshots/` | written by the daily refresh job: per-source hash, tracked values, and the schedule page diff against the dataset. |

## Single-entry rule (the part that matters)

* structure sheet states a limit &rarr; **confirmed**;
* sheet read in full and contains no rebuy, add-on or re-entry clause &rarr; **candidate** (this is the strongest
  state the published sources support; no Venetian sheet publishes a one-entry cap, flag `FG-02`);
* sheet not read &rarr; **unverified**, never ranked;
* any rebuy/add-on, priced re-entry, extra flight, team format, satellite, or a discount bought with a paid
  third-party membership &rarr; excluded and shown on the *Spend-advantage* page.

Bounty events publish a guarantee that explicitly includes total bounties, so they are labelled separately, and
the guarantee-to-buy-in number on every row is a descriptive size ratio &mdash; not a forecast and not an overlay claim.

## Verification

```bash
python3 scripts/build-events.py --check     # datasets match their generator
python3 scripts/build-schedule.py --check
python3 scripts/build-site.py --check       # committed HTML is exactly what the JSON produces
node scripts/scrape-schedule.mjs --selftest # schedule parser tested against a fixture
node scripts/check_site.mjs                 # every data row keeps an https source link; UI ids resolve
```

`.github/workflows/verify.yml` runs these on every pull request and push to `main`.
`.github/workflows/daily-refresh.yml` re-reads all official URLs, snapshots them, and either commits the
snapshots or opens a review pull request when a value the planner depends on moved.

## Preview locally

Open `index.html`, or `python3 -m http.server 8000` and visit <http://localhost:8000>.
The site is fully static: filters, search and the trip calculator run in the browser over
`assets/data.js`, which is generated from the same JSON.

## Known gaps (deliberate, all listed on *Flagged for review*)

No verified 8 AM tournament start exists in this series; no dated room rate could be captured for any property;
no walking duration is verified for any hotel &rarr; poker-room pair; 27 of 37 structure sheets are unread.
Prior sessions' dashboards (`/docs`, `/verified`, `/pages`) were retired in favour of this root site; their data
files remain under `data/` for audit. See [COORDINATION.md](COORDINATION.md).
