Source monitor

A scheduled GitHub Actions job re-fetches every official URL on this list, compares a content hash with the stored one, saves a snapshot when the bytes differ, and marks rows whose source changed. Workflow: .github/workflows/source-monitor.yml (daily at 07:00 Las Vegas time) + scripts/monitor.py. The registry itself is generated from the citations in the published rows (scripts/build_monitor_registry.py), so a new source cannot be left unmonitored by forgetting to add it to a hand-kept list.

Current state: 86 URLs registered · 0 changed · 0 unchanged · 86 baselines still to establish · 0 unreachable on the last run. Last run: the scheduled job has not run in this branch yet.

Read that state correctly. “never fetched” means the monitor has not completed a run against that page yet — it is not a finding that the source is unchanged. Until a baseline hash exists, no row can be marked changed, so the absence of a source changed — re-check badge proves nothing. The dates on the tournament and hotel rows come from a person or agent actually opening the cited page, which is a different and stronger claim than a matching hash.

What each status claims: unchanged the page bytes match the stored hash — the source moved nothing, but a matching hash does not re-verify a value this site transcribed from that page. new first successful fetch; this run only sets the baseline. changed the bytes differ, and every row citing the URL is badged source changed — re-check. unreachable the fetch failed (blocked, timed out, or no route from the runner): the previous status and the row's verification date are left alone, because a failed fetch proves nothing about the page.
